# MAX Chat

Тестовое задание: минимальный интерфейс на React для отправки и получения текстовых сообщений в MAX через GREEN-API.

**Стек:** React 19, TypeScript, Vite, Sass, Lucide, Vitest. Сервер и база данных не нужны.

## Запуск

Требуется Node.js 22.12+ и npm.

```bash
npm ci
npm run dev
```

Откройте Local URL, который напечатает Vite. По умолчанию это http://127.0.0.1:5173; если порт занят, Vite выберет следующий.

```bash
npm test          # тесты контракта API, очереди и состояния чатов
npm run build    # TypeScript + production-сборка в dist/
npm run preview  # просмотр production-сборки
```

Готовую папку `dist/` можно разместить на любом статическом хостинге. Приложение не использует серверные секреты или переменные окружения.

## Подключение MAX

1. В [личном кабинете GREEN-API](https://console.green-api.com/) создайте именно инстанс **MAX** и авторизуйте свой аккаунт MAX. Приложение ожидает `stateInstance: authorized`.
2. В настройках инстанса включите `incomingWebhook: yes`. Для статусов доставки также включите `outgoingWebhook: yes`; для синхронизации исходящих — `outgoingAPIMessageWebhook: yes` и `outgoingMessageWebhook: yes`. Оставьте `webhookUrl` пустым для получения уведомлений через HTTP API.
3. На экране подключения введите `idInstance`, `apiTokenInstance` и **apiUrl своего инстанса**. Предзаполненный `https://3100.api.green-api.com` — пример адреса из документации, а не универсальный сервер.
4. Нажмите «Новый чат», введите номер получателя. Метод `checkAccount` принимает номера с кодами +7 и +375; номер должен быть доступен для поиска в MAX. Приложение получает настоящий `chatId` из ответа API.
5. Отправьте сообщение, затем ответьте из MAX на телефоне получателя. Ответ появится в чате. Enter отправляет сообщение, Shift + Enter добавляет строку.

Не используйте одновременно другое приложение, потребляющее `receiveNotification` того же инстанса: очередь общая, и подтверждённое уведомление больше не возвращается.

## Что реализовано

- Подключение с проверкой авторизации и типа инстанса.
- Создание чата по номеру через `checkAccount`, повторное открытие существующего чата.
- Отправка через `sendMessage`, ограничение MAX в 4000 символов, защита от двойного нажатия.
- Получение через `receiveNotification` с long polling на 30 секунд и подтверждение через `deleteNotification`.
- Защита от повторных уведомлений по `idMessage`, обработка текстов и текстов со ссылками, статусов отправки/доставки/прочтения.
- Несколько чатов, поиск, счётчики непрочитанного, адаптация для телефона.
- Отмена сетевых запросов при выходе, паузы с увеличением интервала при сетевых ошибках.
- Ошибки подключения, неверного номера, недоступного аккаунта, отправки и очереди. При неясном исходе отправки текст остаётся в поле, автоматической повторной отправки нет.
- Отдельный деморежим с тестовой перепиской и автоматическим ответом; он не вызывает GREEN-API.

## Данные и ограничения

Ключи, список чатов и сообщения живут только в памяти вкладки. Перезагрузка и выход очищают их. В `localStorage`, cookies, исходники и логи они не записываются. Запросы идут напрямую на проверенный HTTPS-домен GREEN-API. У сервиса токен входит в путь запроса согласно его API; он виден владельцу вкладки в DevTools. Для общего рабочего продукта предпочтительна серверная авторизация с прокси, здесь сохранена архитектура фронтенд-задания.

История до открытия приложения не загружается. Текстовые уведомления, полученные в текущей сессии, сохраняются перед подтверждением очереди. Неподдерживаемые уведомления (медиа, группы и прочие служебные события) подтверждаются, но не показываются; исходное задание требует только текст. После перезагрузки уже подтверждённые уведомления из очереди восстановить нельзя. Настройки инстанса приложение только читает, изменения в них выполняются в личном кабинете.

Входящий текст выводится как текст React, без HTML. Ссылки в сообщениях не превращаются в активные элементы. Деморежим и реальный аккаунт не смешиваются.

## Структура

```text
src/api/           GREEN-API, long polling, отдельный демоадаптер
src/components/    подключение, создание чата, переписка и их SCSS
src/hooks/         управление сессией переписки
src/state.ts       reducer и обработка уведомлений
src/styles/        токены, базовые правила, компоновка приложения
tests/             тесты API, очереди и reducer
docs/              исследование дизайна, проверка, шаблон сдачи
```

## Проверка

`npm test`: 15 тестов; `npm run build`: успешная сборка. API проверен через подставной HTTP-транспорт с форматом запросов из актуальной [документации MAX](https://green-api.com/v3/docs/). Деморежим проверен в браузере на большом и мобильном экранах. Подробности: [docs/verification.md](docs/verification.md).

Реальный обмен с MAX требует действующего инстанса и ключей пользователя; без них он не проверялся. Инструкция выше описывает полный ручной сценарий приёмки.

Референсы и решения по интерфейсу: [docs/design-references.md](docs/design-references.md).
